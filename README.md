# dayshape — 일정·업무 분리형

개인용 일정 관리 앱 v0.3입니다. GitHub Pages에서 정적 웹앱으로 제공합니다.

사용자가 입력한 데이터는 브라우저에 저장됩니다. 같은 URL을 다른 기기에서 열 수 있지만, 데이터는 기기 간 자동 동기화되지 않습니다. 계정·클라우드 동기화는 아직 연결하지 않았습니다.

## 실행

`dist/index.html` 파일을 브라우저에서 열면 별도 설치 없이 검토할 수 있습니다. ‘예시 일정 넣기’로 샘플을 추가할 수 있습니다. 데이터는 해당 브라우저에 저장됩니다. 실제 개인정보 대신 예시 데이터로 먼저 확인하세요.

```sh
node build.cjs
node --test tests/*.test.cjs
```

## 구현한 기능

- 월 기본, 주·일 전환. 각 날짜에서 미팅과 업무를 별도 영역으로 표시.
- 모바일 월 달력에는 유형별 건수, 선택한 날짜 아래에 상세 목록 표시.
- 항목 등록·수정·삭제, 중요도, 중요 항목만 보기, 완료 숨기기.
- 난이도, 효용성, 시작일, 담당자, 협업자/팀, 프로토·검증·최종 납기, 리마크.
- 주·격주·1/2/3/6/12개월 반복, 반복 종료일, 월말·윤년 처리.
- 반복 수정·삭제는 전체 시리즈에 적용. 완료 여부는 회차·단계별로 독립 저장.
- 반복 종료일은 마지막 회차의 **시작일**을 제한합니다. 그 회차의 후속 납기는 종료일 이후에도 표시됩니다.
- 업무 단계별 납기가 있으면 각 단계만 달력에 표시하며, 없으면 기본 마감일 표시.
- 마우스 오버/키보드 포커스 요약, 클릭·터치 상세 보기.
- 미팅 시작 시 중앙 팝업, 위치·종료 시각, 5분 뒤 알림, 겹치는 알림 순차 표시.
- 브라우저가 열려 있을 때만 알림 제공. 탭 정지·화면 잠금 시 즉시 알림은 보장하지 않으며, 복귀 시 진행 중인 미팅을 확인합니다. 닫힌 앱 푸시/이메일 알림은 미구현.
- JSON 백업 다운로드. 복원·공유·캘린더 외부 연동·AI 자동 등록은 미구현.
- Asia/Seoul 기준. 날짜 계산은 UTC date-only, 미팅 시각은 +09:00 처리.

## 로그인·동기화 연결 준비

소스에는 Supabase 이메일/비밀번호 로그인, 가입, 비밀번호 재설정, 자동 세션 갱신, 계정별 CRUD, 60초 갱신, 낙관적 버전 충돌 방지 어댑터가 포함됩니다. **현재 연결된 서버가 없으므로 실계정 동작·RLS 검증은 아직 하지 않았습니다.** 검토 버전에서 동기화되었다고 표시하지 않습니다.

새 전용 프로젝트에서 `docs/setup.sql`을 실행하고 아래 설정을 완료해야 합니다. 기존 경진대회 프로젝트는 변경하지 않았습니다.

1. 이메일 인증과 승인된 사이트 URL/redirect URL을 설정합니다.
2. `config.js`에 프로젝트 URL과 **publishable key**만 입력합니다. service_role/secret 키는 절대 넣지 않습니다.
3. `node build.cjs`를 실행하고 결과물을 게시합니다.
4. 별도 테스트 계정 A/B로 읽기·쓰기·수정·삭제가 서로 차단되는지 실제 DB에서 검증합니다. 공개 전 RLS advisors도 확인합니다.
5. 가입 확인·비밀번호 재설정 메일, 2개 기기의 저장·충돌 처리, 로그아웃 후 화면 비우기를 검증합니다.

현재 Supabase SDK는 검증 가능한 고정 버전 `2.57.4`의 CDN 모듈을 사용하며, 클라우드 설정이 있을 때만 로딩합니다. 운영 연결 시 최신 보안 점검 및 CSP를 함께 확인하세요. 사용자 데이터는 HTML이나 Git 저장소에 포함되지 않고 전용 DB에 저장됩니다. 로컬 검토 데이터는 로그인 계정으로 자동 업로드하지 않습니다.

## GitHub 배포

전용 저장소: https://github.com/sunup00-hys/dayshape

GitHub Pages는 `main` 브랜치의 루트 폴더를 사용합니다. `node build.cjs`는 `index.html`과 로컬 검토용 `dist/index.html`을 같은 내용으로 생성합니다. 수정용 전체 소스는 `dayshape-source.zip`에 보관합니다. 압축을 풀어 기능 수정 후 테스트와 빌드를 실행하고, 루트 `index.html`과 갱신한 소스 압축파일을 함께 커밋하면 배포됩니다. 정적 호스팅이라 서버 계정이나 유료 런타임 없이 사용할 수 있습니다.

웹앱 코드는 공개되어도 사용자가 브라우저에서 작성한 일정은 저장소에 업로드되지 않습니다. 다른 기기의 일정 동기화나 공유는 현재 제공하지 않습니다.

## 향후 사용자 확장

각 항목은 DB `owner_id`와 연결되고 모든 CRUD에 본인 소유 RLS가 적용되도록 준비했습니다. 다른 사용자도 각자 가입할 수 있으며 서로의 데이터를 볼 수 없습니다. 업무 담당자/팀은 현재 자유 입력 텍스트입니다. 선택적 공유가 필요해지면 membership 모델과 별도 권한 검증을 추가할 수 있습니다. 현재 협업/공유 권한은 없습니다.

## v0.2 개인용 화면 개선

- 모든 업무 카드 오른쪽에 D-n, D-DAY, D+n(기한 초과), 완료를 상시 표시합니다.
- 3일 이내 마감은 주황, 당일/기한 초과는 붉은색. 중요도 높음/최우선과 임박 업무는 별표 및 굵은 글씨.
- 흰색 버튼형 카드, 종류별 표시와 얇은 강조선으로 구분.
- 월·주 화면 오른쪽 위 주말 접기 스위치. 켜면 5열로 확대하며 설정은 이 브라우저에 유지. 주말 데이터는 삭제하지 않습니다.
- 일 보기는 해당 하루를 유지하며 주말 접기 스위치가 비활성화됩니다. 한국 날짜가 바뀌면 D-day를 갱신합니다.


## v0.3 회사 달력과 표 / 엑셀

- 중요 카드의 배경은 보라색, 3일 이내 주황색, 당일·초과 납기는 붉은색. 별표·굵은 글씨·우측 D-day 표시 유지.
- 각 날짜 칸 가운데 정렬된 + 버튼으로 해당 날짜 등록창을 바로 열 수 있습니다. 월·주·일·모바일 지원.
- 2026~2027년 공휴일은 공식 발표 및 2026년 법령 개정과 대조했습니다. 노동절·제헌절, 음력 공휴일과 대체공휴일, 2026년 지방선거일 포함.
- 2028~2050년은 2026-10-30 법령과 한국 음력에 따른 **예상** 공휴일입니다. 미래 선거일·임시공휴일 및 법령 변경은 자동 갱신하지 않습니다. 지원 범위 밖 연도는 안내를 표시합니다.
- 회사 일정·휴일 설정: 해프 / 공동연차 / 전체 일정 / 추가 휴일. 이름, 날짜 범위, 종일·오전·오후, 반복, 반복 종료일, 리마크. 수정·삭제는 시리즈 전체에 적용.
- 회사 일정과 공휴일은 날짜 옆에 이름을 표시하고 날짜 칸을 옅은 붉은색으로 칠합니다. ‘전체 일정’도 사용자의 요청대로 같은 색으로 표시하며 법정 공휴일을 의미하지 않습니다.
- 등록한 회사 일정은 일반 일정과 같은 저장소에 보존하고 JSON 백업에도 포함됩니다. 휴일이 있어도 미팅·업무 날짜를 자동 이동하지 않습니다.
- 캘린더에는 간단한 제목과 납기를 표시하고 마우스 오버/키보드 포커스에서 주요 업무 필드와 리마크 400자까지 표시합니다. 전체 내용은 클릭하여 확인합니다.
- 일정·업무 표 탭: 위쪽 일정(미팅+회사 일정), 아래쪽 업무. 등록된 전체 항목을 원본 1행씩 표시하며 반복 규칙과 종료일을 별도 열에 둡니다.
- 엑셀 내보내기는 서버 없이 OOXML `.xlsx`를 생성합니다. 두 시트(일정/업무), 제목행·열 머리글·필터·행 고정, 숫자 날짜, 한글/줄바꿈, 전체 업무 필드와 회차·단계 완료 기록을 보존합니다. 문자열은 수식으로 해석하지 않습니다.
- 자동 공휴일은 표 및 엑셀에서 제외하며 회사에서 직접 등록한 일정은 포함합니다. 무한 반복 회차는 무한 행으로 펼치지 않습니다.
- 자동 다운로드가 시작되지 않는 환경에서는 ‘엑셀 파일 저장’ 링크를 사용할 수 있습니다.
